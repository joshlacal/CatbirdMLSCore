# Repository Guidelines

How to work inside CatbirdMLSCore. Keep changes small and consistent with the package layout. Architecture, invariants and the FFI workflow are in [CLAUDE.md](CLAUDE.md).

## Build & Test Workflow

Agents SHOULD build and test autonomously, through the `ctl` slot when working in the shared workspace (`CTL_AGENT=<agent> ~/.cargo/bin/ctl run --slot xcode -- <cmd>`). Verify changes before reporting completion.

See `~/Developer/.claude/AGENTS.md` for global agent guidelines.

## Project Structure & Modules
- `Sources/CatbirdMLSCore/Client` — `MLSAppGroupStorage`, `MLSPushExtensionProcessor` (NSE), `MLSClientCoordinator`.
- `Sources/CatbirdMLSCore/KeyStore` — Keychain `PlatformKeyStore` + `PushKeystore`.
- `Sources/CatbirdMLSCore/Transport` — Petrel-backed `PlatformTransport` + `PushFetchTransport`.
- `Sources/CatbirdMLSCore/Service` — outbound request validation, public PDS reads, blob crypto.
- `Sources/CatbirdMLSCore/Models`, `Extensions` — payload/presentation types and helpers. No storage layer lives in Swift; Rust (`catbird-mls`) owns the SQLCipher database.
- `Sources/CatbirdMLS/CatbirdMLS.swift` — generated by `Scripts/rebuild-ffi.sh`; do not edit manually.
- `Sources/CatbirdMLSFFI.xcframework` — local native build from `../catbird-mls` (gitignored).
- `DevelopmentIntegration/` — sibling-integration wrapper and the Space artifact manifests (receipts).

## Build, Test, and Development Commands
- `DevelopmentIntegration/run-local.sh swift test --scratch-path .build-local-integration` — test against the exact sibling checkouts with graph and framework verification.
- `swift build` / `swift test` — plain SwiftPM; also uses the siblings and a marker-verified local framework.
- `CMAKE_POLICY_VERSION_MINIMUM=3.5 Scripts/rebuild-ffi.sh` — rebuild the framework and generated interface from sibling `catbird-mls`, `catbird-atproto` and `labyrinth`; then regenerate and verify `DevelopmentIntegration/spaces-apple-artifact-manifest.json` (see `DevelopmentIntegration/README.md`).
- `python3 -m unittest discover -s Scripts/tests -v` — FFI tooling tests.

## Coding Style & Naming Conventions
- Swift 6 tools, Swift 5 language mode (for UniFFI bindings), iOS 18 / macOS 15.
- 2-space indentation; explicit access control (`private`/`fileprivate`) and `final` where appropriate.
- Types/protocols: PascalCase. Methods/properties: camelCase. Enum cases: lowerCamel.
- Keep FFI-generated code untouched; MLS behavior belongs in `catbird-mls`, not here.

## Testing Guidelines
- Add XCTest suites under `Tests/CatbirdMLSCoreTests/`. Use `NativeArchiveMockNetwork` instead of real servers, and canonical UUIDv4 device IDs.
- Cross-process, crash and federation cases belong in `../catbird-sim` (see CLAUDE.md).
- Never boot or touch the `iPhone 18 Pro Max` simulator (`51D953A5-461C-42C0-A947-C13930EE1BE2`); use `iPhone 17 Pro` or a scratch simulator.

## Commit & Pull Request Guidelines
- Commits: concise, imperative summaries; include ticket/issue IDs when available.
- Call out FFI rebuilds and regenerated artifacts, and name the `catbird-mls` / `catbird-atproto` commits the framework was built from (the manifest records them).
- Red holds: no production deploys, production DB migrations, or pushes/merges to `main` without Josh's explicit approval. Publishing a new FFI release also needs approval.

## Security & Configuration Tips
- Never commit secrets; keys stay in the Keychain. Never log ciphertext, keys or raw DIDs.
- After changing Rust FFI, rebuild with `Scripts/rebuild-ffi.sh` and regenerate the manifest before testing; the generated interface and the framework must come from the same build.
